# 产品设计影响与原型

UI 影响与产品设计影响分别判定。主流程、导航、权限体验、异常/恢复、状态流转或 API 反推才触发页面流、状态矩阵和原型校准；纯文案、token、间距或无行为的孤立视觉修复不自动触发完整产品设计。

命中产品设计影响时使用 `yss-design-system` → `yss-prototype-stage` → 独立 `prototype-review`；H1/H2 使用根 `DESIGN.md` 驱动的离线 HTML/CSS/JavaScript，默认 Data Quality 浅色主题，暗色或紧凑模式仅在明确选择时启用。分别验证视觉与流程，绑定当前规范和 Token 摘要。原型不调用生产 `yss-ui`。

原型用于验证产品设计，不替代生产实现、OpenAPI 或 Slice 合同。生产还原需同一页面、视口与交互状态的可定位基线及允许差异，不能仅凭截图或 type-check 宣布还原通过。

本地终点为 `work-unit.strategic-design-handoff`，完成后 `next_route: null`；本仓不生成技术设计、OpenAPI、父/垂直切片 Ticket、Slice Implementation Contract 或运行时代码，实施请求转交下游研发 Profile。 参见 [[Spec基线]]、[[Fresh验证与独立审查]]。
